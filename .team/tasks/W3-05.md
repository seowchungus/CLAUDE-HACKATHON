# W3-05: Eval page honesty (mock ≠ measured) + bad-day block
Owner: W3 · Timebox: 10 min (fold in with W3-04) · Depends on: W3-03 · Proposal §8, rubric "Honest evaluation"

`eval/results.json` in the repo is a **mock** run (`summary.llm == "mock"`, scripted agents, n=5), but the Eval page shows the green **MEASURED** badge and an 80% consensus rate. Judges must never see scripted numbers presented as measured LLM results.

## Changes (`web/` only)
- If `summary.llm` is `"mock"`: replace the MEASURED badge with an amber **"SCRIPTED AGENTS (mock): not an LLM result"** badge, and grey out the LLM tiles (consensus, by R2, schema failure, latency, tokens). B0/B1 numbers stay normal (they are deterministic and real).
- If `summary.llm` is `"none"`: show "Deterministic baselines only (B0/B1)"; LLM tiles render "not run".
- Show `n` and `llm` in the header line, e.g. `N=30 · agents: gemini-3.5-flash-lite (live)`.
- If `bad_day` is present (v1.2.1, W1-07): a small "Bad-day replay" card: airport, date, n_flights, B0 vs B1 totals (bank delay, misconnects, overtime, J), b0_infeasible, b1_escalate, with the label "deterministic baselines only; the LLM negotiation is evaluated on the N set".

## Acceptance
1. With the current mock file: amber SCRIPTED badge, no MEASURED badge.
2. `npm run build` succeeds.
