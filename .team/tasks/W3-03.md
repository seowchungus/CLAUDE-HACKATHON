# W3-03: Contracts v1.1 alignment, chaos/kill/approve controls, eval page, replay
Owner: W3 · Timebox: 45 min (target done 13:25) · Depends on: CONTRACTS v1.1 · Proposal: §4.4, §7.6–7.9, §10 demo insurance

Read the v1.1 changelog at the bottom of `docs/CONTRACTS.md` first. The fixtures were regenerated: `run_log.jsonl` now verifies, so your badge should show "chain verified ✓", and flight ids are unpadded.

## 1. v1.1 alignment
- `GET /api/runs/{run_id}/bundle` → `{bundle, map}` for the run's own scenario (mock: the fixture; live: the bundle the run was built from, incl. chaos). The UI loads map/wall/Gantt from this once a run exists, so chaos changes (blocked taxiway, failed gate, new ETA) show up.
- Chaos: child chaos accumulates (you do this already). If the parent is still running, cancel it (`Coordinator.cancel()` from W2-03; in mock, emit `run_ended {final_state: "SUPERSEDED"}`) and switch the UI to the child stream.
- Approve: `409` before `awaiting_approval`; on ESCALATE only `OVERRIDE` with an option_id; response `final_hash` = head before the approval entry (same as `approved.data.final_hash`); the envelope `log_hash` = the approval entry's hash. Fix the mock to match. The UI uses the POST response.
- Match log entries to events by `log_hash`, never by seq. Handle `run_ended.final_state == "SUPERSEDED"`.
- MOCK mode: unknown scenario ids → 404, handled in the UI.

## 2. Controls (proposal §7.6, 7.7, 7.9)
- **Chaos menu**: the 4 kinds with sensible default params (RUNWAY_CLOSURE aar_factor 0.5; TAXIWAY_BLOCK taxiway picker from `scenario.taxiways`; GATE_FAILURE gate picker; WEATHER_CELL). Clicking starts the child run and the room re-negotiates.
- **Kill the LLM** toggle (big, red when off) → `POST /api/kill`; the next run shows the fallback instantly. Show `llm_enabled` from `/health`.
- **Approve / Override** with an option picker for Override, a "by" field, and a note; then show "Signed: <final_hash short>" and close the chain in the log drawer.
- **Scripted failure runs**: a small "Demo scenarios" menu that starts mock modes `deadlock`, `unsafe`, `hallucinate` (W2-03 exposes them; add `mode` to `POST /api/runs` body as an optional field, which is additive) and shows a "SCRIPTED" badge when `run_started.data.scripted` is true.

## 3. Eval results page (proposal §7.8, §8)
A second view reading `GET /api/eval`: summary tiles (consensus rate, % by R2, fallback/escalate rate, unsafe proposals blocked vs **unsafe plans executed (must be 0)**, schema failure rate, latency p50/p95, tokens), J vs B0/B1 bars, the per-scenario table. Show a "MEASURED" badge only if `measured: true`; render `null` as "not run", never as 0. Handle 404 ("eval not run yet"). Use `eval/results.json` on disk (W1 has a mock-mode file) to develop against.

## 4. Replay (demo insurance)
`GET /api/replay/{name}/stream` plays `api/hero_cache/<name>.jsonl` with the original timing (capped at 1.5 s per gap) and the UI shows a "REPLAY (recorded <ts>)" badge. Add `python -m api.record_hero <scenario_id> <name>` that runs a live run and saves its envelopes to `api/hero_cache/<name>.jsonl`. Don't record yet; that happens after integration.
