# W1-03: Constraint checker H1–H7, fallback, bundle, CLI milestone
Owner: W1 · Timebox: 35 min (target done 13:10) · Depends on: W1-02 · Proposal: §5.2, §5.3, §8.2 B0/B1

## Files
- `core/constraints.py`: `check_option`, `check_all` → `CheckReport` with exactly 7 `ConstraintResult`s in H1..H7 order, each with `value`, `threshold` and a ≤120-char `detail`. Rules per proposal §5.2 with thresholds from `config.thresholds`:
  - H1 `separation_margin_s >= 0`; H2 `arrivals_this_hour <= aar_reduced`; H3 `fuel_at_landing_min >= fuel_final_reserve_min`; H4 gate free over the occupancy window, not out_of_service, size ≥ aircraft_size; H5 `flight_crew_duty_remaining_min − eta_shift − hold >= 0` and `ramp_overtime_min <= ramp_overtime_hard_cap_min`; H6 `taxi_path_ok`; H7 `turbulence_idx < turbulence_severe`.
- `core/fallback.py`: `fcfs(s)` (B0: eta_shift 0 → next free runway slot, first free compatible gate, as_filed; option_id `opt_fcfs`) and `solve(s, opts, checks, weights)` (B1: filter feasible → min J → tie-break by lowest eta_shift then option_id; none feasible → `ESCALATE` with reason "no feasible option: diversion candidate").
- `core/bundle.py`: `build_bundle(scenario_id, chaos=None)` and `build_bundle_from_scenario(s)` → `ScenarioBundle` (checks include `opt_fcfs`).
- `core/cli.py`: `python -m core.cli <scenario_id|--dev N>` prints the scenario header (real vs synthetic tagged), the options table with key metrics, the **checker grid** (options × H1–H7, ✓/✗), and the fallback plan. **This is the 1:30 milestone.**
- `core/cli.py --export <scenario_id> <out.json>`: writes `{bundle, map: null}` JSON (W2/W3 use it to swap the fixture for a real scenario).
- `tests/test_constraints.py`, `tests/test_fallback.py`: each of H1–H7 has a failing and a passing case; fallback never returns an infeasible option; all-infeasible → ESCALATE; fallback works without any import from `agents/` (proves the LLM can be off).

## Acceptance criteria
1. `python -m core.cli --dev 0` prints the options, the 7-column grid and the fallback plan for a real row in < 5 s.
2. Each dev row has at least one infeasible option and at least one feasible option (tune the synthetic generators if not; note it if a row legitimately has no feasible option → ESCALATE is fine for one).
3. `pytest -q tests/` passes.
4. Append a DONE line with the CLI output of one dev row pasted in (first 30 lines).
