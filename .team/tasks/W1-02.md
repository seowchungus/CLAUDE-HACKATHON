# W1-02: Scenario builder, metrics, option generator
Owner: W1 · Timebox: 40 min (target done 12:35) · Depends on: W1-01 · Proposal: §2.2, §5.1

## Files
- `core/scenario.py`: `list_scenarios(limit, airport, date)` and `build_scenario(scenario_id) -> Scenario` per CONTRACTS.md §1.1.
  - Real first: disrupted row; bank = arrivals into DEST same date, sched_arr ±`config.scenario.bank_window_min`; connections = same-airline departures from DEST 30–150 min after sched arr; `aar_nominal` = peak observed hourly arrivals at DEST that day; `next_departure_min` = the same tail's next departure from DEST that day if found (provenance `real`), else seeded (`synthetic`).
  - Synthetic second, all from `random.Random(seed)`, seed = stable hash of `(date, airline, flight_number)` (e.g. `int(hashlib.sha256(...).hexdigest()[:8], 16)`; **not** Python's `hash()`): wake per flight (distance heuristic + noise), `aircraft_size`, `fuel_at_fix_min` (≈ 45–60), crew duty, ramp shift end, `pax_connecting` (3–25), turbulence by FP (`reroute_weather` lowest; scale up with WEATHER_DELAY), gate template (12 gates A1–C4, sizes, taxi paths over taxiways A–D, a few seeded occupied intervals around the ETA so some gates conflict).
  - `aar_reduced = round(aar_nominal * factor)` (config.thresholds.aar_weather_factor by WEATHER_DELAY band; late-aircraft-only rows use factor 1.0, still labelled synthetic).
  - `provenance` covers every field (see fixture for the expected keys, e.g. `"bank.wake": "synthetic"`).
- `core/metrics.py`: `compute_metrics(s, eta_shift_min, gate, fp) -> Metrics`. Suggested simplified rules (document them in the docstring; labelled "illustrative, not certified"):
  - `eta_new = base_eta + eta_shift`; runway slots spaced `60/aar_reduced` min; `runway_slot` = first free slot ≥ eta_new given bank `est_arr_min` occupancy.
  - `separation_margin_s` = (slot − preceding arrival) in s − `wake_separation_s[leader-follower]`.
  - `arrivals_this_hour` = bank arrivals in [slot−30, slot+30) + 1; `throughput_loss = max(0, arrivals_this_hour − aar_reduced)`.
  - FP effects: `speed_reduction` absorbs up to 15 min of shift en route at low fuel cost (≈0.3 min fuel per min); `hold_10/hold_20` → `hold_min` and ≈1.0 fuel min per hold min; `reroute_weather` +8 min flight, +6 fuel min, lowest turbulence; remaining shift not absorbed is flown at normal burn. `fuel_at_landing = fuel_at_fix − planned_burn_fix_to_land(≈20) − extra_fuel`.
  - `misconnected_pax` = Σ pax of connections whose `sched_dep − (eta_new + taxi_in) < 45` (MCT).
  - Gate: free window around `[eta_new+taxi_in, next_departure or +60)`; `taxi_path_ok` = no blocked taxiway in path.
  - `turnaround_buffer = next_departure − (eta_new + taxi_in + min_turnaround)`; `ramp_overtime = max(0, eta_new + taxi_in + 30 − ramp_shift_end)`.
  - `bank_delay_added` = minutes pushed onto bank flights whose slot we take.
  - `cost_J` per proposal §5.3 with `config.fallback_weights`.
- `core/options.py`: `make_option`, `generate_options(s)` (grid eta × gates × FP → Pareto front on (bank_delay, extra_fuel, misconnects, overtime) → 6–8 candidates incl. at least one each that ATC (min bank delay), PILOT (min misconnects, no hold) and GROUND (min overtime) would prefer; ids `opt_1..`; **include 1–2 infeasible-but-tempting options** so the checker has something to catch), `counter_allowed_values(s)`.

## Acceptance criteria
1. `build_scenario(id)` twice → identical JSON (reproducible). Works for all 5 dev rows.
2. Every Scenario field appears in `provenance`; synthetic ones say `"synthetic"`.
3. `generate_options` returns 6–8 options with distinct (eta, gate, fp) and non-trivial trade-offs (print a table for one dev row).
4. `tests/test_metrics.py`: hold costs more fuel than speed reduction for the same shift; misconnects are non-decreasing with eta_shift; blocked taxiway → `taxi_path_ok=False`.

Constraint checker and fallback (W1-03). Chaos and map (W1-04).
