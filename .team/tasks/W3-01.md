# W3-01: API in mock mode + console skeleton with live negotiation room
Owner: W3 · Timebox: 45 min (target done 12:00) · Depends on: fixtures only · Proposal: §7, §9

## Files
- `api/server.py`: FastAPI app implementing **every endpoint in CONTRACTS.md §4** (use `sse-starlette` for SSE). With `MOCK=1`:
  - `/api/scenarios` → `docs/fixtures/scenarios_list.json`; `/api/scenarios/{id}` → `docs/fixtures/scenario_bundle.json` for any id
  - `POST /api/runs` → new run_id; `/api/runs/{id}/stream` replays `docs/fixtures/run_events.jsonl` with ~600 ms gaps (rewrite `run_id` to the new id)
  - `/chaos` → new run_id (replays the same stream, with `run_started.data.parent_run_id` and `chaos_applied` set); `/approve` → `{ok, final_hash}` and pushes an `approved` event on the open stream; `/kill` toggles a flag returned by `/health`
  - `/log` → `docs/fixtures/run_log.jsonl` as `application/x-ndjson` download; `/verify` → recompute the chain with the contract formula (stdlib `hashlib`; switch to `core.log.verify_chain` at integration)
  - Design for live mode now: a `RunManager` that holds per-run event lists and an `asyncio.Queue` per subscriber; mock mode is just one producer. Live mode (later) = `agents.coordinator.Coordinator(...).run()` as the producer.
  - CORS for the Vite dev server; also serve `web/dist` at `/` when built.
- `web/`: Vite + React + TypeScript + Tailwind. `web/src/types.ts` mirrors CONTRACTS.md (hand-written TS types). One `useRunStream(runId)` hook that reduces SSE envelopes into state.
- UI layout (single page, dark):
  1. **Scenario bar**: flight, route, date, delay type + minutes (REAL tag), and a compact list of synthetic fields with `SYNTHETIC` tags
  2. **Round tracker** `R1 → R2 → R3 → CONSENSUS/FALLBACK` with the current state large and clear
  3. **Negotiation room**: three columns ATC / PILOT / GROUND; each `agent_position` becomes a card (action badge, ranking, acceptable set, counter, red lines, rationale, cites, latency/model/status). "thinking…" placeholder on `agent_thinking`. `counter_checked` rejected → red card with reason (shake animation); `veto` → red banner.
  4. **Decision panel**: plan from `consensus`/`fallback`, decision source, narration, and Approve / Override buttons (POST approve).
  5. Placeholders (boxes) for map, constraint wall, Gantt (W3-02).
- Run instructions in `api/README.md`: `MOCK=1 uvicorn api.server:app --port 8000` + `cd web && npm run dev`.

## Acceptance criteria
1. With `MOCK=1`, opening the console and clicking "Run" streams the fixture: cards appear round by round, the PILOT counter shows as rejected (H4), the GROUND veto banner shows (H3), consensus R2 shows opt_c1, Approve works.
2. `curl -N localhost:8000/api/runs/<id>/stream` shows `event:`/`data:` lines matching CONTRACTS.md §3.
3. `/api/runs/<id>/verify` returns `ok: true` for the fixture log.
4. `npm run build` succeeds.

## Out of scope
Map, constraint wall, Gantt, eval page (W3-02 and later).
