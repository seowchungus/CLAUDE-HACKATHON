1. **Path traversal in the SPA catch-all serves `.env` (API key) and any repo file (`api/server.py`, `spa()`).** `FileResponse(DIST / path)` with an encoded `../` escapes `web/dist`:
   - `GET /..%2f..%2f.env` → **200, the `.env` file** (I checked size and key-name presence only; I did not print it);
   - `GET /..%2F..%2Fconfig.yaml` → 200.
   This breaks the non-negotiable "keys only in `.env`", because the server hands them out. Anyone on the venue Wi-Fi can read them if the server binds `0.0.0.0`. Fix: `f = (DIST / path).resolve()` and serve it only if `f.is_file() and f.is_relative_to(DIST.resolve())`; else `index.html`. Add a test: `TestClient(app).get("/..%2f..%2f.env")` must not contain `GEMINI_API_KEY`.
2. **Live `run_started` is changed after it was logged (`_live_producer`).** `env["data"]["parent_run_id"] = run.parent_run_id` patches the envelope after the coordinator has already hashed and written the entry with `parent_run_id: null`. The UI then shows a parent the log doesn't contain, so the envelope no longer matches the log entry for its `log_hash` (§3: the log payload is "the SSE data payload, verbatim"). Fix: `Coordinator(bundle, run.run_id, config=CONFIG, parent_run_id=run.parent_run_id)` (the parameter exists), and never mutate `env`.
3. **Live approve doesn't publish the sign-off or map refusals (`RunManager.approve`).**
   (a) The coordinator's refusals (`ok: False` + `error`: not finished, unknown or infeasible option, and after W2-04 the APPROVE/ESCALATE/double-approve rules) come back as HTTP 200 `{ok: false}`. Map them to `409`, with the error in `detail`.
   (b) After `run_ended`, `Coordinator.run()` has stopped iterating, so the `approved` envelope never reaches `run.events` or subscribers. The code looks for `res["event"]`, which the coordinator doesn't return. Publish `run.coordinator.approved` (set by `approve()`) when it isn't in `run.events` yet. Otherwise the record endpoint says "Human sign-off: pending" after a real sign-off.
4. **The mock kill stream duplicates `log_hash` (`_mock_fallback_stream`).** All five events reuse `run_started`'s `log_hash`, and none are written to `run.log_entries`. v1.1 makes clients match by `log_hash`, so the kill demo in MOCK mode shows wrong log links, and the log drawer shows the consensus fixture log for a fallback run. Build the mock log entries with `entry_hash` the same way mock approve does, and give each envelope its own hash.
5. **`POST /api/runs/{id}/chaos` takes an untyped `dict`.** A malformed body (wrong `kind`, missing params) is accepted, and the live producer later dies with a fatal `error` event instead of a `422`. Type the body as `core.types.ChaosEvent` (fall back to a local copy of the model in MOCK).
